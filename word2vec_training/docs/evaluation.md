# 评估口径与已有实验记录

## 方法

Word2Vec 检索方案使用分词后的原始词向量均值，再做 L2 归一化；重复词按词次计权，未知词跳过。查询和完整候选库进行精确分块余弦排名，不使用近似索引。指标对查询做宏平均，相关性为二值标签。

- **Hit@K**：前 K 个结果中至少有一个正例的查询比例。
- **Recall@K**：每个查询召回的正例数 / 该查询全部标注正例数，再取平均。
- **MRR@10**：前十名内首个正例的倒数排名均值。
- **NDCG@10**：前十名二值相关性的归一化折损累计增益。
- **词次覆盖率**：词表内词次数 / 总词次数，不是检索准确率。

全 OOV 或均值为零的查询计为未命中；零向量文档不排名，但相关性分母不变。同分按候选文件中的顺序处理。

## 两类评估集

`--eval-data` 将句对文件的正负例文本汇集成候选库，合并同文 query 的正例。句对标签不一定覆盖汇集后全部相关文档；未被标为正例的候选，不一定在语义上不相关。

`--corpus/--queries` 使用明确的文档 ID 和多正例标签，保留不同 ID 的同文文档。DuRetrieval 的这类数据可做独立段落检索基线，但公开标签也不保证完备，更不能直接代替具体业务验收。

`--diagnose-self-matches` 只针对当前查询排除完全同文且未标为正例的候选，文本比较仅去除首尾空白；保留标注正例和分母。对照需要重新检索完整剩余候选库，指标上升来自候选范围变化，不是模型提升。标点变体或其他近义句不会被这个规则排除。

优先复核 24 条共同前十未命中和 1 条 Word2Vec 独有前十命中，再补跑全量 2,000 查询。当前本地未取得真实逐查询文件，不能仅凭汇总判断这些案例属于漏标、截断还是模型漏检；[复核工具与全量命令](next-evaluation.md)用于完成这一步。

## 公平对照与复核

`compare_bge.py` 从 Word2Vec 的原始 `results.jsonl` 复用查询 ID 和顺序，而不是重新抽样。校验原始数据哈希、查询文本、正例及可重算的指标后，使用同一候选库、排序函数和指标函数计算 BGE 结果。

Word2Vec 使用全文平均；BGE 默认使用带查询指令的 CLS 向量，归一化后排名，长度为查询 64 / 段落 256 tokenizer tokens。长度、指令与版本写入 `audit.json`；改变设置应生成新报告。这里比较完整检索方案，不宣称编码方法、截断策略或上游训练数据相同。

优先核对 `NDCG@10`、`MRR@10`、`Recall@10`，同时检查双方独有命中和共同失败的查询。`review.jsonl` 只是定位问题的案例集，不能据此估算总体人工准确率。是否用于实际检索或 RAG，还需要固定业务语料、标签及下游回答评估。
