# 07 μP、学习率调度对比、Muon/SOAP：三块实验怎么做（2026-11-17）

属于 06 里的第 2 块"优化与超参"。三块共用同一个代理模型和同一份数据，结论都用 bits/字节和种子噪声来判断。

## 共同设置

**代理模型**：d768_l16，与第一批学习率扫描相同。
- 约 1.25 亿参数：16 层，宽 768，12 头 × 64 维，GQA 12/4，SwiGLU 2048，词表 32000。
- 嵌入与输出层共享权重。

**训练配置**
- 每步 262,144 token（64 × 4 × 1024），warmup 300 步。
- AdamW（β = 0.9 / 0.95，ε = 1e-8），wd = 0.1，只作用于矩阵。
- 梯度裁剪 1.0；bf16 + torch.compile。

**训练时长**（吞吐约 16.2 万 tok/s）
| token 数 | 时长 | 说明 |
|---|---|---|
| 10 亿 | 约 1.7 小时 | |
| 25 亿 | 约 4.3 小时 | 20 token/参数，约 Chinchilla 最优 |
| 50 亿 | 约 8.6 小时 | |

**指标**
- 主指标：按评测权重加权的 bits/字节。
- 辅助指标：分来源 bits/字节、合成算术准确率、cloze。
- 训练中记录：裁剪生效占比、更新量与权重之比、逐层梯度 RMS。

**噪声与配对**
- 噪声大小用第一批消融的 3 个种子估计，今晚出结果；目前粗估 σ ≈ 0.003。
- 代码里同一个 seed 同时决定两件事：初始化（`torch.manual_seed`）和数据顺序（`MixtureSampler`）。
- 因此对比组一律用同一个 seed，即配对比较。两组初始化和数据完全相同，差值的噪声远小于两次独立训练。
- 关键结论再用第二个 seed 配对复核。成立的条件是两条都满足：
  - 两个 seed 上差值方向一致；
  - 差值在两个 seed 之间的变化明显小于差值本身。

**比较时点**：只比学习率衰减结束后的终点。中途曲线会误导，两组的排名可能在衰减阶段翻转。

**数据**
- 今晚 tok_ab 的代理数据会按计划删除，给路线 A 腾出数据盘。
- 重建：在路线 A 第 2 段训练期间（约 11-20 夜到 11-21），用 CPU 按 v1 配比重建约 50 亿 token（约 10GB）。
- 去污染：用今晚数据工程统计出的污染清单，剔除与 v1 验证 / 测试文档近似重复的文档。
- 三块实验和第 1 块 scaling law 共用这份数据。

**评测**：沿用 v1 的验证 / 测试集，长度 1024。

**峰值学习率**
- 默认 1e-3，按第一批消融的结论定：1e-3 与 2e-3 的差别在噪声内。
- 如果今晚 3 个种子显示 2e-3 显著更好，就改用 2e-3。

## 一、学习率调度对比（核心约 30 小时，全做约 43 小时）

### 要回答的问题
1. **WSD 对余弦**：token 预算固定时，WSD（恒定学习率 + 冷却）能否追平或超过余弦？冷却多长、什么形状最好？
2. **终点**：衰减到 0 和衰减到峰值的 10%，最终 loss 差多少？
3. **冷却收益**：冷却阶段 loss 骤降多少？原因可以用"河谷"图景解释：
   - 恒定学习率阶段，下降主要被梯度噪声挡住；
   - 降低学习率后，噪声项消失，loss 很快落到谷底。
4. **为什么 WSD 适合续训**：不知道最终要训多久时（比如续训，路线 A 就是这种情况），一条主线可以派生出多个预算的结果。
5. **Schedule-Free**：能否不用调度、任何时刻的检查点都直接可用？代价是什么？

### 实验组
所有组用同一个 seed（1234），峰值学习率 1e-3。★ 为核心组。

| 组 | 做法 | token | 时长 |
|---|---|---|---|
| ★ W0 主线 | warmup 后恒定 1e-3 训到 40 亿 token。在 5、10、15、20、22.5、40 亿 token 处各存一份完整检查点（权重 + 优化器 + 采样器状态） | 40 亿 | 6.9h |
| ★ W-预算 | 从 5 / 10 / 20 / 40 亿处各分出一段冷却，长度为该预算的 20%，线性降到 0。得到 6.25 / 12.5 / 25 / 50 亿四个预算的结果 | 18.75 亿 | 3.2h |
| ★ W-形状 | 25 亿预算下，另外两种冷却形状：线性降到 10%（现行做法）、1−√（Hägele 等人提出） | 10 亿 | 1.7h |
| W-长度 | 25 亿预算下，冷却 10%（从 22.5 亿处分出）和冷却 40%（从 15 亿处分出） | 12.5 亿 | 2.1h |
| ★ C 余弦 | 余弦衰减到 10%。6.25 / 12.5 / 25 亿三个预算各从头跑一次（余弦不能复用主线，这本身就是要体会的区别） | 43.75 亿 | 7.5h |
| ★ D2Z | warmup 后全程线性衰减到 0，25 亿 | 25 亿 | 4.3h |
| ★ SF | Schedule-Free AdamW，25 亿，学习率 2e-3（通常需要比带调度的 AdamW 更大的学习率） | 25 亿 | 4.3h |
| SF-2 | 同上，学习率 4e-3 | 25 亿 | 4.3h |
| 复核 | seed = 2，重跑两组：W（主线到 20 亿 + 冷却）、余弦 25 亿 | 50 亿 | 8.6h |
| 稳健性（可选） | W 和余弦在 2e-3 下各跑一次，避免结论只在一个学习率上成立 | 50 亿 | 8.6h |

### 要改的代码
- **调度函数**：把 `wsd_lr` 扩成通用调度函数，支持以下几种：
  - constant；
  - wsd（参数：衰减比例；形状 linear / cosine / 1-sqrt；终点比例）；
  - cosine（参数：终点比例）；
  - linear。
- **里程碑检查点**：主线在指定 token 处保存检查点，不轮转、不删除。按每个约 1.5GB 估计，6 个约 9GB。
- **分支运行**：从里程碑检查点恢复后换成冷却调度，跑到指定 token。
  - 权重、优化器、采样器、步数都要精确恢复；ablate.py 已有断点续训，在它上面扩展。
- **Schedule-Free**：移植 facebookresearch/schedule_free 的 `AdamWScheduleFree`。
  - 评估和存检查点之前调用 `optimizer.eval()`，切到平均权重；训练时调用 `optimizer.train()` 切回。
- **额外记录**：每组记录冷却开始前和结束后的 loss（两者之差即冷却收益），以及完整的学习率曲线。

### 怎么分析
1. **预算曲线**：画"终点 loss 对 token 预算"的图。WSD（一条主线 + 分支）和余弦（每个预算单独跑）放在同一张图上。
2. **配对差值**：25 亿预算下，算各组与 W（线性到 0、冷却 20%）的配对差值。配对噪声用复核组估计。
3. **冷却分析**：
   - 冷却收益随预算怎么变；
   - 冷却长度从 10% 到 20% 再到 40%，每加长一档多换来多少收益。
4. **SF 的随时可用性**：在 12.5 亿 token 处，拿 SF 的中途检查点（没有冷却）和同预算的 WSD 分支比，看差多少。
5. **进阶：预测调度的效果**
   - 用多幂律（Luo 等人）在 2–3 条曲线上拟合；
   - 用拟合结果预测其余调度的整条 loss 曲线；
   - 预测误差小于噪声，说明你真正理解了调度对 loss 的作用。

### 文献预期（作为对照，不作为结论）
- **Hägele 等人**：恒定 + 冷却与余弦相当或更好；1−√ 冷却好于线性；不同训练长度可以复用同一条主线。
- **Bergsma 等人**：线性衰减到 0（D2Z）在多种规模、批量、数据集上都好于衰减到 10%；token/参数越大，优势越大。
- **Song 等人（NeurIPS 2025）**：Schedule-Free AdamW 不需要衰减阶段，也不需要额外的权重平均，就能沿谷底前进。
- **2026 年的一份技术报告**：Schedule-Free 放大到大批量、大模型时需要额外修正。
- **对我们的影响**：在这个规模上，好调度之间可能只差 0.5–1%，约 0.005–0.01 bits/字节，接近噪声。所以必须配对比较。

### 掌握标准
- 能解释冷却为什么带来 loss 骤降。
- 给定 token 预算，能选出调度方式和冷却长度。
- 会用一条主线得到多个预算的结果。
- 进阶：训练前就能预测某个调度的最终 loss。

## 二、μP（核心约 20 小时，全做约 32 小时）

### 我们的模型现在是标准参数化（SP）
- **初始化**：所有 Linear 和 Embedding 的初始化 std = 0.02；残差输出层（o_proj、down_proj）为 0.02/√(2L)。
- **权重共享**：嵌入与输出层共享权重。
- **学习率**：所有参数用同一个学习率。
- **注意力**：打分除以 √head_dim。
- **问题**：v1（d1024_l40，4.84 亿参数）用的峰值学习率是 4e-4，而 16 层代理模型的最优学习率在 1e-3 以上。换宽度、换深度时学习率该怎么变，目前全靠经验。

### μP 要改的地方
- 适用于 Adam；按 EleutherAI 与 Cerebras 的实践指南。
- 记号：m = 宽度 / 256。m = 1 时 μP 与 SP 完全一致，可以用来做回归测试。

| 部件 | 现在（SP） | μP |
|---|---|---|
| 嵌入（与输出层共享） | std 0.02，学习率 η | 不变 |
| 隐藏矩阵 q/k/v/o、gate/up/down | std 0.02，学习率 η | 初始化方差 ÷m（即 std ÷√m），学习率 ÷m |
| 残差输出层的 1/√(2L) | 有 | 保留（只与深度有关，与宽度无关） |
| 输出 logits | x·Wᵀ | 乘 α_out/m |
| 嵌入输出 | 原样 | 乘 α_in（可调常数，默认 1） |
| 注意力打分 | ÷√64 | 指南要求改成 ÷head_dim。我们固定 head_dim = 64、只增加头数，这一项在各宽度下是常数，可以不改 |
| RMSNorm 增益 | 学习率 η | 不变 |
| weight decay | PyTorch AdamW，每步衰减量 = 学习率 × wd | wd 保持 0.1，理由见下 |

**weight decay 为什么保持 0.1 就够**
- 隐藏层学习率 ÷m 之后，每步实际衰减量也跟着 ÷m，即按 1/宽度缩小。
- 这正好符合 Qiu 等人的结论："独立 weight decay 按 1/宽度缩放接近最优"。
- 扫描里会加一组对照来验证：实际衰减量不随宽度变化。

**训练循环要改**：现在所有参数组统一赋同一个学习率，要改成每组 `lr × lr_mult`。

### 步骤
1. **坐标检查**（几分钟 GPU，也可以用 CPU）
   - 设置：宽度 128 / 256 / 512 / 1024 / 2048，2–4 层，训练 10 步，3 个种子。
   - 记录：每类层的激活平均绝对值，包括嵌入、注意力输出、FFN 输出、残差流、logits。
   - 通过标准：各宽度的曲线重合，不随宽度增长。
   - SP 应该不通过，作为对照。
2. **宽度扫描**（约 13 小时）
   - 模型：8 层，head_dim 64，SwiGLU 中间维 = 2.75 × 宽度。用多头注意力（kv 头数 = 头数），避免小宽度下 GQA 分组除不尽。
   - 宽度：128 / 256 / 512 / 1024。
   - 训练：每组 3 亿 token，每步 26 万 token，warmup 100 步。
   - 学习率：SP 和 μP 各扫 7 档，从 2⁻¹² 到 2⁻⁶（约 2.4e-4 到 1.6e-2）。
   - 可选：μP 最优附近 3 档各加一个种子（约 3 小时）。
   - 预期：SP 的最优学习率随宽度增大而变小；μP 的最优位置不动；μP 下每个学习率都是越宽越好。
3. **迁移验证**（约 6–11 小时）
   - 按指南，代理模型的深度要与目标模型一致。
   - 目标模型：第 1 块 scaling law 里 2.6 亿参数的那个。
   - 做法：
     1. 在同深度、宽度 256 的小模型上扫学习率；
     2. 把最优值直接用到 2.6 亿模型上；
     3. 用 ×0.5、×1、×2 三档验证它确实在最优附近。
   - 通过后，scaling law 的 4 个规模都用这个学习率，不再分别扫描。
4. **可选：深度迁移**（约 5 小时）
   - 背景：μP 只管宽度。CompleteP（Cerebras，NeurIPS 2025）给残差分支乘 1/L 并相应调整超参，可以跨深度迁移。
   - 设置：宽度 256，深度 4 / 8 / 16 / 32；μP 与 μP+CompleteP 各扫 5 档学习率。
   - 能回答的问题：结合宽度结论，可以对"v1 用 4e-4 是否偏小"给出有依据的估计。
   - 注意：v1 训了 250 亿 token。训练越长，最优学习率越低，这一点要在估计里单独换算。

### μP 不管的东西
- **需要重新确认的**：批量大小、训练 token 数、学习率调度。指南明确说，改了调度或模型结构就要重调。
- **深度**：需要 CompleteP 一类的做法。
- **代理模型的批量**：不能低于临界批量，否则迁移结果会偏。
- **Adam 的 ε**：宽度变大后，隐藏层梯度会变小。要记录各层梯度 RMS 与 ε = 1e-8 的比值，接近时调小 ε。

### 掌握标准
- 能在自己的代码里从零实现 μP，并用坐标检查证明实现正确。
- 能说清哪些超参随宽度迁移、哪些不迁移。
- 能在宽 256 的小模型上调好超参，直接用到大模型。

## 三、Muon 与 SOAP（核心约 37 小时，加 50 亿预算约 48 小时）

### Muon
- **来源**：服务器 venv 的 PyTorch 是 2.9.0，自带 `torch.optim.Muon`。
- **算法**：
  1. 动量 0.95，Nesterov；
  2. 用 Newton–Schulz 迭代 5 步把更新正交化，系数为 3.4445 / −4.775 / 2.0315；
  3. 加解耦 weight decay。
- **适用范围**：只给 Transformer 块里的 2D 矩阵用，即 q/k/v/o 和 gate/up/down。我们的模型里这些本来就是分开的矩阵，不用拆。
- **其余参数**：嵌入（与输出层共享）和 RMSNorm 继续用 AdamW。
- **缩放方式**：用 `adjust_lr_fn="match_rms_adamw"`，即 Moonshot 的做法。
  - 每次更新乘 0.2·√max(A,B)，使更新量 RMS 与 AdamW 一致；
  - 这样学习率和 weight decay 可以从 AdamW 的最优值出发扫描，不用另起一套量级。
- **开销**：在这个规模上，Newton–Schulz 每步约 2×10¹² FLOP，而每步训练计算约 2×10¹⁷ FLOP，可以忽略。
- **训练循环要改**：
  - 两个优化器同时设学习率、同时 step；
  - 检查点里同时保存两份优化器状态；
  - 梯度裁剪仍在 step 前统一做。
- **规模放大的风险**：Kimi K2 报告 Muon 比 AdamW 更容易出现注意力 logit 爆炸，他们用 QK-Clip 解决（在 Muon 更新后直接缩放 q、k 投影矩阵）。我们的模型没有 QK-norm，所以要监控（见下文"稳定性要盯的"）。

### SOAP
- **来源**：PyTorch 不自带，移植作者的单文件实现（nikhilvyas/SOAP，约 150 行）。
- **原理**：在 Shampoo 预条件器的特征基里跑 Adam。比 Adam 只多一个超参：特征基的更新频率，论文用 10。
- **默认设置**：
  - β = (0.95, 0.95)；
  - 维度超过上限（默认 10000）的那一侧不做预条件，所以词表那一侧（32000）用单位阵。
- **显存**：每个矩阵多存左右两个统计量及其特征向量。在这个规模上多几 GB，没有问题。
- **风险**：2026 年的一项研究报告 SOAP 在大批量下会不稳定，并提出了每步做 QR 正交化等修正。我们每步 26 万 token，属于中等批量，但要盯 loss 尖峰。

### 单元测试（CPU 上就能做）
- **正交化**：随机矩阵经 Newton–Schulz 后，奇异值应全部落在约 0.5–1.5 之间。这组系数为了速度，故意不严格收敛到 1。
- **更新量 RMS**：match_rms_adamw 模式下约为 0.2。
- **能训练**：在小模型上 loss 能下降。
- **断点续训**：检查点保存、恢复后继续训练，结果与不中断一致。
- **参数分组**：每个参数恰好由一个优化器管理，不重复、不遗漏。

### 实验
1. **学习率扫描**（12.5 亿 token，约 22 小时）
   - 调度：WSD 冷却，形状和长度取第一块的最优。固定用 WSD，是为了让第一块的分支结果直接当 AdamW 的尺子。
   - 种子：seed = 1234。
   - AdamW：补跑 2e-3、4e-3 两档；1e-3 直接取第一块的分支结果。
   - Muon、SOAP：各扫 4 档，1e-3、2e-3、4e-3、8e-3。
   - 每档的跑法：先跑恒定学习率的主线到 10 亿 token，再从 10 亿处分出冷却段。
2. **25 亿 token**（约 15 小时）
   - 各优化器的最优那一档：主线从 10 亿续到 20 亿，再冷却到 25 亿，前面的计算全部复用。
   - 再用 seed = 2 跑一次。
   - AdamW 的两个种子直接取自第一块。
3. **可选：50 亿 token**（2 倍 Chinchilla，约 11 小时）
   - Muon、SOAP 的主线续到 40 亿，再冷却到 50 亿。
   - AdamW 用第一块主线的 50 亿分支。

### 怎么算"快多少"
- **token 加速**（Wen 等人的做法）：
  1. 用第一块 AdamW 在 6.25 / 12.5 / 25 / 50 亿 token 的终点 loss，拟合 L(D) = E + A·D^(−α)；
  2. Muon 或 SOAP 用 D 个 token 达到某个 loss，从拟合式反推 AdamW 达到同样 loss 需要多少 token，记为 D′；
  3. 加速 = D′ / D。
- **墙钟加速** = token 加速 × （AdamW 每步时间 ÷ 新优化器每步时间）。
- **其他要看的**：
  - 学习率曲线的宽窄，即对学习率是否更不敏感；
  - 下游指标（算术、cloze）是否同步变好。

### 稳定性要盯的
- 每层的更新量 RMS 和权重 RMS。
- 最大注意力 logit：每次评估记录各层最大的 QK 打分，超过阈值就告警。
- loss 尖峰次数、裁剪生效占比。

### 公平比较的规则
这是这一块真正要学的东西。
1. **最优对最优**：每个优化器都要调到自己的最优学习率。只沿用 AdamW 的超参，对别的优化器不公平（Wen 等人）。
2. **只比终点**：只比衰减结束后的结果。
3. **条件一致**：同 token、同批量、同调度、同 warmup；配对 seed；关键结论用两个 seed。
4. **两种加速都报**：同时报 token 加速和墙钟加速。
5. **结论只对这个规模成立**：
   - Wen 等人测到，加速从 1 亿参数的约 1.4 倍降到 12 亿参数的约 1.1 倍。
   - Qiu 等人认为，原因主要是超参没有正确地随规模缩放。用 μP 学习率加 1/宽度 weight decay 后，1.9 亿到 14 亿参数都能保持约 1.4 倍。
   - Moonshot 报告的是约 2 倍。
   - 所以想知道"放大后还剩多少"，要把 μP 的结论和这一块的结果结合起来。
   - 可选扩展（约 1 天）：在宽度 512 / 768 / 1024 三个规模上各训 20 token/参数，比较 AdamW 和 Muon；学习率按 μP 从最小的规模迁移。

### 掌握标准
- 能读懂 Muon、SOAP 的每一步，并能自己实现。
- 能设计公平的优化器对比。
- 看到"某优化器快 X 倍"时，能判断在自己的规模和预算下大概值多少。
